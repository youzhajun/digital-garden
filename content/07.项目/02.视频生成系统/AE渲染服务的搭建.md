# 项目介绍
包含 AE 模板视频生成 和 FFmpeg 短视频拼接 两大子系统，实现基于模板的自动化视频合成（替换资源+渲染）与视频片段的智能重组拼接，提升视频内容生产效率。

# 如何调用 AE

借助开源项目 `ae-nexrender` 实现对 ae 软件的调用，该软件的本质是解析用户的配置`json`信息，构建出符合 ` Adobe ExtendScript`  的脚本，并调用 `Afterfx.exe` 服务进行视频渲染服务。

# 集群的架构是怎样的？如何监控 Worker 节点的状态和资源利用率？如何避免单点故障？

`ae-nexrender` 开源软件提供能完善的解决方案。以下是`ae-nexrender` 的工作流程。
- 通过 `server` 服务管理中心管理 `worker` 节点，启动 `worker` 时需指定注册到的 `server` 地址。
- `server` 对外暴露接口，包括创建任务、查询节点状态、 删除任务等接口
- `server` 接收到创建任务请求后会将任务通过负载均衡的方式转发到负责此任务的  `worker` 中
- `server` 与 `worker` 间有通信进程，`worker` 会将执行结果告知 `server`
- `server` 回实时监控所有 `worker` 的状态，当`worker`状态异常时，新的任务不会指派到该节点。



# 解析 AE 工程文件 (AEPX) 是如何实现的？

- 首先 `aepx` 是 `ae` 的工程文件，记录了整个 `ae` 工程的信息（轨道、资源、转场）等各种信息。
- `aepx` 是 `xml` 格式，不同版本的 `ae` 可能有所却别
- 借助了 ae 中的一个插件，通过该插件解析成 `json` ，该插件只会解析一些图层、静态资源、时长、位置等信息。
- 服务通过解析上述的 `json` 再进行结构化保存。

## 解析过程中遇到了什么问题？如何解决的？

- 图层类型多样，有的图层是绘制的，处理起来很麻烦。（过滤掉这些图层，只取需要替换的图层）
- 图层位置计算复杂，视频是动的。（制定 ae 制作标准，将一个视频规定为1个或多个视频场景，只取场景第一帧）
