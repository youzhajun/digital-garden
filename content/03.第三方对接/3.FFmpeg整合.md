4. 编写相关代码 - 任务类 （实现`Runnable`）
```java
	package online.youzhajun.ffmpeg;  
  
	import org.apache.commons.exec.CommandLine;  
	import org.apache.commons.exec.DefaultExecutor;  
	import org.apache.commons.exec.PumpStreamHandler;  
	  
	import java.io.File;  
	import java.io.FileOutputStream;  
	import java.io.IOException;  
	import java.io.OutputStream;  
	import java.util.UUID;  
	import java.util.function.Consumer;  
	  
	public class FFmpegTask implements Runnable {  
	  
	    private final String command;  
	    private final String taskId;  
	    private final String logDirectory;  
	    private final Consumer<FFmpegTaskResult> callback;  
	  
	    private FFmpegTaskStatus status;  
	    private String logFilePath;  
	    private String errorMessage;  
	    private long startTime;  
	    private long endTime;  
	  
	    public FFmpegTask(String command, String logDirectory, Consumer<FFmpegTaskResult> callback) {  
	        this.command = command;  
	        this.taskId = UUID.randomUUID().toString();  
	        this.logDirectory = logDirectory;  
	        this.callback = callback;  
	        this.status = FFmpegTaskStatus.PENDING;  
	    }  
	  
	    public String getTaskId() {  
	        return taskId;  
	    }  
	  
	    public FFmpegTaskStatus getStatus() {  
	        return status;  
	    }  
	  
	    public String getLogFilePath() {  
	        return logFilePath;  
	    }  
	  
	    public String getErrorMessage() {  
	        return errorMessage;  
	    }  
	  
	    @Override  
	    public void run() {  
	        this.status = FFmpegTaskStatus.RUNNING;  
	        this.startTime = System.currentTimeMillis();  
	        this.logFilePath = logDirectory + File.separator + "ffmpeg_task_" + taskId + ".log";  
	        File logFile = new File(logFilePath);  
	  
	        try (OutputStream outputStream = new FileOutputStream(logFile)) {  
	            CommandLine cmdLine = CommandLine.parse(command);  
	            DefaultExecutor executor = new DefaultExecutor();  
	            PumpStreamHandler pumpStreamHandler = new PumpStreamHandler(outputStream);  
	            executor.setStreamHandler(pumpStreamHandler);  
	  
	            int exitValue = executor.execute(cmdLine);  
	  
	            if (exitValue == 0) {  
	                this.status = FFmpegTaskStatus.COMPLETED;  
	            } else {  
	                this.status = FFmpegTaskStatus.FAILED;  
	                this.errorMessage = "FFmpeg command exited with code: " + exitValue;  
	            }  
	  
	        } catch (IOException e) {  
	            this.status = FFmpegTaskStatus.FAILED;  
	            this.errorMessage = "IOException during FFmpeg execution: " + e.getMessage();  
	            e.printStackTrace(); // 打印堆栈信息以便调试  
	        } catch (Exception e) {  
	            this.status = FFmpegTaskStatus.FAILED;  
	            this.errorMessage = "Unexpected error during FFmpeg execution: " + e.getMessage();  
	            e.printStackTrace(); // 打印堆栈信息以便调试  
	        } finally {  
	            this.endTime = System.currentTimeMillis();  
	            // 调用回调函数通知任务完成  
	            if (callback != null) {  
	                callback.accept(new FFmpegTaskResult(status, errorMessage, logFilePath, startTime, endTime));  
	            }  
	        }  
	    }  
	}
```

5. 编写相关代码 - 任务执行类
```java
	package online.youzhajun.ffmpeg;  
  
	import java.io.File;  
	import java.util.concurrent.*;  
	import java.util.function.Consumer;  
	  
	public class FFmpegProcessor {  
	  
	    private final ThreadPoolExecutor executorService;  
	    private final String logDirectory;  
	  
	    /**  
	     * 构造函数  
	     * @param maxConcurrentTasks 最大并发任务数  
	     * @param queueCapacity 等待队列容量  
	     * @param logDirectory 日志文件保存目录  
	     */  
	    public FFmpegProcessor(int maxConcurrentTasks, int queueCapacity, String logDirectory) {  
	        if (maxConcurrentTasks <= 0) {  
	            throw new IllegalArgumentException("maxConcurrentTasks must be greater than 0");  
	        }  
	        if (queueCapacity < 0) {  
	            throw new IllegalArgumentException("queueCapacity must be non-negative");  
	        }  
	  
	        this.logDirectory = logDirectory;  
	        // 确保日志目录存在  
	        File dir = new File(logDirectory);  
	        if (!dir.exists()) {  
	            dir.mkdirs();  
	        }  
	  
	        // 使用有界队列来控制等待任务数量  
	        BlockingQueue<Runnable> workQueue = new ArrayBlockingQueue<>(queueCapacity);  
	  
	        this.executorService = new ThreadPoolExecutor(  
	                maxConcurrentTasks,       // 核心线程数，同时运行的最大任务数  
	                maxConcurrentTasks,       // 最大线程数，与核心线程数相同，避免创建过多线程  
	                60L,                      // 空闲线程存活时间  
	                TimeUnit.SECONDS,         // 时间单位  
	                workQueue,                // 工作队列  
	                new ThreadFactory() {     // 自定义线程工厂，方便调试  
	                    private int counter = 0;  
	                    @Override  
	                    public Thread newThread(Runnable r) {  
	                        Thread thread = new Thread(r, "FFmpeg-Task-Worker-" + counter++);  
	                        thread.setDaemon(true); // 设置为守护线程，应用关闭时自动退出  
	                        return thread;  
	                    }  
	                },  
	                new RejectedExecutionHandler() { // 拒绝策略：当队列满时，抛出RejectedExecutionException  
	                    @Override  
	                    public void rejectedExecution(Runnable r, ThreadPoolExecutor executor) {  
	                        if (!executor.isShutdown()) {  
	                            throw new RejectedExecutionException("FFmpeg task queue is full, max capacity: " + queueCapacity);  
	                        }  
	                    }  
	                }  
	        );  
	    }  
	  
	    /**  
	     * 提交一个FFmpeg任务  
	     * @param ffmpegCommand 要执行的FFmpeg命令  
	     * @param callback 任务完成时的回调函数，接收FFmpegTaskResult  
	     * @return 任务的唯一ID  
	     * @throws RejectedExecutionException 如果任务队列已满  
	     */  
	    public String submitTask(String ffmpegCommand, Consumer<FFmpegTaskResult> callback) throws RejectedExecutionException {  
	        FFmpegTask task = new FFmpegTask(ffmpegCommand, logDirectory, callback);  
	        executorService.submit(task);  
	        System.out.println("Submitted FFmpeg task: " + task.getTaskId() + ", Command: " + ffmpegCommand);  
	        return task.getTaskId();  
	    }  
	  
	    /**  
	     * 获取当前活动任务数  
	     * @return  
	     */    
	     public int getActiveTaskCount() {  
	        return executorService.getActiveCount();  
	    }  
	  
	    /**  
	     * 获取等待队列中的任务数  
	     * @return  
	     */    
	     public int getQueueSize() {  
	        return executorService.getQueue().size();  
	    }  
	  
	    /**  
	     * 关闭处理器，等待所有已提交任务完成  
	     */  
	    public void shutdown() {  
	        executorService.shutdown();  
	        try {  
	            if (!executorService.awaitTermination(60, TimeUnit.SECONDS)) {  
	                System.err.println("FFmpegProcessor did not terminate in 60 seconds, forcing shutdown.");  
	                executorService.shutdownNow();  
	            }  
	        } catch (InterruptedException e) {  
	            Thread.currentThread().interrupt();  
	            System.err.println("FFmpegProcessor shutdown interrupted.");  
	            executorService.shutdownNow();  
	        }  
	    }  
	  
	    /**  
	     * 立即关闭处理器，中断所有正在运行的任务  
	     */  
	    public void shutdownNow() {  
	        executorService.shutdownNow();  
	    }  
	}
```

```java
	public class Main {  
  
    public static void main(String[] args) throws InterruptedException {  
        // 设置最大并发任务数和队列容量  
        int maxConcurrentTasks = 2; // 同时处理2个FFmpeg任务  
        int queueCapacity = 5;      // 最多等待5个任务  
        String logDir = "ffmpeg_logs"; // 日志文件保存目录  
  
        FFmpegProcessor processor = new FFmpegProcessor(maxConcurrentTasks, queueCapacity, logDir);  
  
        // 提交多个FFmpeg任务  
        for (int i = 0; i < 10; i++) {  
            String inputFilePath = "test.mp4"; // 替换为你的输入文件路径  
            String outputFilePath = "result_" + i + ".mp4"; // 替换为你的输出文件路径  
            // 一个简单的FFmpeg命令示例：将mp4转为mp4，并指定编码器  
            String ffmpegCommand = String.format("ffmpeg -i %s -c:v libx264 -preset fast -crf 23 %s", inputFilePath, outputFilePath);  
  
            final int taskIndex = i; // final或effectively final for lambda  
  
            try {  
                String taskId = processor.submitTask(ffmpegCommand, result -> {  
                    System.out.println("----------------------------------------");  
                    System.out.println("Task " + result.getLogFilePath() + " finished.");  
                    System.out.println("Status: " + result.getStatus());  
                    if (result.getStatus() == FFmpegTaskStatus.FAILED) {  
                        System.out.println("Error: " + result.getErrorMessage());  
                    }  
                    System.out.println("Log file: " + result.getLogFilePath());  
                    System.out.println("Duration: " + (result.getEndTime() - result.getStartTime()) + "ms");  
                    System.out.println("----------------------------------------");  
  
                    // 可以读取日志文件内容进行进一步处理  
                    readLogFile(result.getLogFilePath());  
                });  
                System.out.println("Task " + taskId + " submitted successfully.");  
            } catch (RejectedExecutionException e) {  
                System.err.println("Failed to submit task " + taskIndex + ": " + e.getMessage());  
            }  
        }  
  
        // 打印当前处理器状态  
        System.out.println("Active tasks: " + processor.getActiveTaskCount());  
        System.out.println("Queued tasks: " + processor.getQueueSize());  
  
        // 等待一段时间，让任务执行  
        Thread.sleep(20000000); // 根据实际FFmpeg执行时间调整  
  
        // 关闭处理器  
        System.out.println("Shutting down FFmpeg processor...");  
        processor.shutdown();  
        System.out.println("FFmpeg processor shut down.");  
  
        // 再次打印处理器状态，此时应为0  
        System.out.println("Active tasks after shutdown: " + processor.getActiveTaskCount());  
        System.out.println("Queued tasks after shutdown: " + processor.getQueueSize());  
    }  
  
    private static void readLogFile(String logFilePath) {  
        System.out.println("--- Reading log file: " + logFilePath + " ---");  
        try (BufferedReader reader = new BufferedReader(new FileReader(logFilePath))) {  
            String line;  
            while ((line = reader.readLine()) != null) {  
                System.out.println(line);  
            }  
        } catch (IOException e) {  
            System.err.println("Error reading log file " + logFilePath + ": " + e.getMessage());  
        }  
        System.out.println("--- End of log file ---");  
    }  
}
```

# 问题

### 如何调用的 ffmpeg
通过 `common-exec` 库进行调用 `ffmpeg`，使用 `ThreadPoolExecutor` 进行线程管理。
- 启动 ffmpeg 进程，通过 `common-exec` 的 `DefaultExecutor.execte()` 启动，该方法内部会调用 `java.long.ProcessBuilder` 来创建新的进程
- 进程启动，它会独立运行，直到命令执行完毕或被外部干预。
- FFmpeg进程的生命周期由其自身的执行完成而终止。`DefaultExecutor` 会等待进程完成，并获取其退出码。
- **优雅关闭**: 当`FFmpegProcessor`被调用`shutdown()`时，它会调用`ThreadPoolExecutor`的`shutdown()`方法。这会阻止新的任务提交，并允许已提交但未执行的任务以及正在执行的任务完成。通过`awaitTermination()`，我们可以等待所有任务在指定时间内完成，从而确保FFmpeg进程有足够的时间自然退出。
- **强制关闭**: 如果在`awaitTermination()`指定时间内任务未能完成，或者直接调用`shutdownNow()`，`ThreadPoolExecutor`会尝试中断所有正在执行的任务。`common-exec` 内部会尝试终止底层进程（例如，在Unix上发送SIGTERM或SIGKILL，在Windows上调用`terminate()`），从而强制结束FFmpeg进程的生命周期。

## 如何记录错误信息

FFmpeg进程的标准输出（stdout）和标准错误输出（stderr）都通过 `org.apache.commons.exec.PumpStreamHandler` 进行统一处理。
- 在 `FFmpegTask` 中，我创建了一个 `FileOutputStream` 并将其传递给 `PumpStreamHandler`。这意味着FFmpeg进程的**所有**控制台输出（包括日志、警告和错误信息）都会被重定向并写入到这个特定的日志文件中 (`ffmpeg_task_<taskId>.log`)。
- `DefaultExecutor.execute()`方法会返回FFmpeg进程的退出码。如果退出码非零（通常0表示成功），我将其视为任务失败。
- 在 `try-catch` 块中，我捕获了 `IOException` 和其他 `Exception`，并将错误信息保存到 `task` 的 `errorMessage` 中
- 通过`FFmpegTaskResult`对象，这些错误信息和日志文件路径会被返回给调用方，以便进行进一步分析和处理。


## 如何进行资源回收？
- **文件流资源回收**：日志文件 (`FileOutputStream`) 在`FFmpegTask`中使用try-with-resources语句进行管理。这意味着无论FFmpeg命令执行成功、失败或抛出异常，`FileOutputStream`都会被自动关闭，确保文件句柄被释放。
- **进程资源回收**： `common-exec`库负责管理底层`java.lang.Process`对象的资源回收。当FFmpeg进程退出后，其相关的系统资源（如进程句柄、内存等）会由操作系统和JVM进行回收。`common-exec`会确保底层的输入输出流都被正确关闭。
- **线程资源回收**：`ThreadPoolExecutor`负责线程的生命周期管理。当任务完成或线程池关闭时，线程会被回收或终止。

## 遇到过 FFmpeg 执行超时或崩溃的问题吗？如何解决的？
是的，在实际项目中，FFmpeg处理耗时且资源密集，执行超时或崩溃是常见的问题。
1. ffmpeg 执行时间超时。
	 - 解决方案：根据任务复杂度，合理设置任务超时时长。
 2. ffmpeg 崩溃。FFmpeg进程在执行过程中意外终止，可能没有返回正常的退出码，或者直接导致JVM崩溃（极少见）原因有以下几点：
	- 输入文件损坏或格式不正确。
	- FFmpeg命令参数错误，导致无法处理。
	- 内存不足（FFmpeg处理大文件时可能消耗大量内存）。
