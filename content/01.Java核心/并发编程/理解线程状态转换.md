- `NEW` ： 只是创建 `java` 对象，还未与系统创建线程
- `RNNABLE` : `new` 出的线程调用 `start()` 方法后变为 `RNNABLE` 状态，并在操作系统层面创建出新的线程。在操作系统层面  `RNNABLE`  涵盖 **运行状态 、阻塞状态、可运行状态**
- `WAITING`
- `TIME_WAIING`

## `runnable` ==> `waiting` 

### 图中线段2： `wait、notify`
1. 线程使用 `synchronized(obj)` 获得锁之后
2. 调用 `obj.wait()` 方法，线程由 `runnable --> waiting`
3. 调用 `obj.notify() 、 obj.notifyAll()、 t.interrupt()` 时，多个线程开始竞争锁
	1. 竞争成功，`waiting -> runnable`
	2. 竞争失败，`waiting -> blocked`

```java
@Slf4j  
public class Test25 {  
  
    private static final Object lock = new Object();  
  
    public static void main(String[] args) throws InterruptedException {  
  
        new Thread(() -> {  
            synchronized (lock) {  
                try {  
                    lock.wait();  
                } catch (InterruptedException e) {  
                    throw new RuntimeException(e);  
                }  
                log.info("t1, 执行");  
            }  
        }, "t1").start();  
  
        new Thread(() -> {  
            synchronized (lock) {  
                try {  
                    lock.wait();  
                } catch (InterruptedException e) {  
                    throw new RuntimeException(e);  
                }  
                log.info("t2, 执行");  
            }  
        }, "t2").start();  
        Thread.sleep(1000);  
  
        synchronized (lock) {  
            log.info("main 开始咯");  
            // notify 随机唤醒 操作系统决定  
            // lock.notify();  
            // 全部唤醒，由 waiting 转为 blocked（主线程还没释放锁的时间点）， 然后再次竞争，成功的线程 由 blocked 转为 running            lock.notifyAll();  
        }  
  
    }  
  
  
}
```

### 图中线段3： `join`
1. 当前线程调用 `t.join()` 方法时，当前线程从 `RUNNABLE --> WAITING`
	- **注意是当前线程在 t 线程对象的监视器上等待**
2. t 线程运行结束，或是调用了当前线程的 `interrupt()` 时，当前线程从 `WAITING --> RUNNABLE`
```java
public static void main(String[] args) throws InterruptedException {  
  
    Thread t1 = new Thread("t1") {  
        @Override  
        public void run() {  
            log.info("t1 running");  
            try {  
                TimeUnit.SECONDS.sleep(3);  
                log.info("t1 end");  
            } catch (InterruptedException e) {  
                throw new RuntimeException(e);  
            }  
        }  
    };  
  
    t1.start();  
    // 主线程等待t1执行完成  
    t1.join(4000);  
    // t1 结束后，当前线程从 waiting -》 runnable    log.info("main running");  
    log.info("main end");  
}
```

### 图中线段4： `LockSupport.park() `
1. 当前线程调用 `LockSupport.park()` 方法让当前线程由 `RUNNABLE --> WAITING`
2. 其他线程调用 `LockSupport.unpark(目标线程对象)` 或调用了线程的 `interrupt()` 会让目标线程从 `WAITTING --> RUNNABLE`

## `runnable` ==> `timed_waiting` 
### 图中线段5： `obj.wait(等待时长) 设置时间`
1. t 线程使用 `synchronized(obj)` 获得锁之后
2. 调用 `obj.wait(等待时长)` 方法，线程由 `runnable --> timed_waiting
3. t 线程等待的时长超过了限制的时长，或者调用了 `obj.notify()、 obj.notifyAll() 、t.interrupt()`。开始竞争锁
	1. 竞争成功， `timed_waiting --> runnabled`
	2. 竞争失败， `timed_waiting --> blocked`

### 图中线段6： `t.join(等待时长) 设置时间`
1. 当前线程调用 `t.join(等待时长)` 方法时，当前线程从 `RUNNABLE --> TIMEDD_WAITING`
2. 等待时长结束，或 t 线程运行结束，或是调用了当前线程的 `interrupt()` 时，当前线程从 `TIMED_WAITING --> RUNNABLE`

### 图中线段7： `sleep(等待时长)`
1. 当前线程调用 `Thread.sleep(等待时长)` 后，当前线程由 `RUNNABLE --> TIMED_WAITING`
2. 当前线程等待时长超过了设置时长后，当前线程由 `TIMED_WAITING --> RUNNABLE`

### 图中线段8： `类park()方法: parkNanos(等待时长)`
`LockSupport` 提供了带有时长的 `park` 方法: `parkNanos(等待时长 单位毫秒)` 、 `parkUtil(等待时长 秒)`  
1. 调用上述方法后，当前线程从 `RUNNABLE --> TIMED_WAITING`
2. 调用了 `LockSupport.unpark()` 或调用了线程的 `interrupt()` 会让目标线程从 `TIMED_WAITING --> RUNNABLE`


## `RUNNABLE` <==> `BLOCKED` 
-  当前线程在争夺锁的过程中竞争失败，从 `RUNNABLE --> BLOCKED`
-  持有 `obj` 锁线程同步代码块执行结束之后，会唤醒该对象上的所有 `BLOCKDE` 线程进行竞争，如果竞争成功 `BLOCKED --> RUNNABLE` 其他线程失败仍未 `BLOCKED`

## `RUNNABLE` <==> `TERMINATED`
- 当前线程执行完毕，线程状态：`RUNNABLE --> TERMINATED`
