# 介绍

- 核心思想：动态的给一个对象添加额外的职责（功能）。

## 能干什么？

想象一下要用代码实现一个咖啡店，基础咖啡种类有**浓缩**、**拿铁**， 配料有牛奶、奶油、摩卡。
- 如果使用继承，就需要为每一种可能的组合创建一个类，"浓缩+奶咖啡"，“浓缩+奶油”，“双倍浓缩”，“拿铁+双倍奶”，“拿铁双倍浓缩”等等组合，如果以后加抹茶一种配料，可能衍生出来十几个类，难以维护。
- **开闭原则（OCP）：** 软件实体（类、模块、函数等）应该对**扩展开放**（可以添加新功能），对**修改关闭**（尽量不修改现有代码）。继承在添加新功能时常常需要修改现有的父类或创建大量子类，违反了OCP。装饰器模式能更好地遵循OCP。
- 动态组合：希望可用原料灵活的动态组合出成品咖啡。

# 实现

## 具体思路 

- **组件接口（Component）：** 定义所有对象（原始对象和装饰器对象）的共同接口。通常是抽象类或接口。（例子：`Coffee` 接口）
- **具体组件（Concrete Component）：** 实现`Component`接口，是需要被装饰的**核心对象**、**原始对象**。（例子：`Espresso`, `Latte`）
- **装饰器基类（Decorator）：** 实现 `component` 接口，并持有一个 `Component` 对象的引用（通常通过构造函数传入）。引用就是要装饰的对象，它还定义了装饰的行为。
- **具体装饰器（Concrete Decorator）：** 继承自`Decorator`基类，负责**添加具体的额外职责（功能）**。它在调用被装饰对象的方法**之前**或**之后**添加自己的新行为。

## 步骤

1. 组件接口

	```java
		// 组件接口 - 定义咖啡的核心行为
		public interface Coffee {
		    double getCost(); // 获取价格
		    String getDescription(); // 获取描述
		}
	```

2. 具体组件

	```java
		// 具体组件 - 浓缩咖啡
		public class Espresso implements Coffee {
			@Override
			public double getCost() {
				return 5.0; // 基础价格
			}
			@Override
			public String getDescription() {
				return "Espresso"; // 基础描述
			}
		}
		
		// 具体组件 - 拿铁
		public class Latte implements Coffee {
			@Override
			public double getCost() {
				return 10.0;
			}
			@Override
			public String getDescription() {
				return "Latte";
			}
		}
	```

3. 编写装饰器基类

	```java
		// 装饰器基类 - 实现Coffee接口并持有被装饰的Coffee对象
		public abstract class CoffeeDecorator implements Coffee {
		    protected Coffee decoratedCoffee; // 被装饰的咖啡对象
		
		    public CoffeeDecorator(Coffee coffee) {
		        this.decoratedCoffee = coffee;
		    }
		
		    // 基类的方法直接委托给被装饰对象
		    @Override
		    public double getCost() {
		        return decoratedCoffee.getCost();
		    }
		    @Override
		    public String getDescription() {
		        return decoratedCoffee.getDescription();
		    }
		}
	```

4. 编写具体装饰类

	```java
		// 具体装饰器 - 牛奶
		public class MilkDecorator extends CoffeeDecorator {
		    public MilkDecorator(Coffee coffee) {
		        super(coffee); // 调用父类构造器，传入被装饰对象
		    }
		
		    @Override
		    public double getCost() {
		        return super.getCost() + 4.50; // 在基础价格上加牛奶的钱
		    }
		    @Override
		    public String getDescription() {
		        return super.getDescription() + ", Milk"; // 在基础描述上加", Milk"
		    }
		}
		
		// 具体装饰器 - 摩卡
		public class MochaDecorator extends CoffeeDecorator {
		    public MochaDecorator(Coffee coffee) {
		        super(coffee);
		    }
		    @Override
		    public double getCost() {
		        return super.getCost() + 2.0;
		    }
		    @Override
		    public String getDescription() {
		        return super.getDescription() + ", Mocha";
		    }
		}
		
		// 具体装饰器 - 奶油
		public class WhipDecorator extends CoffeeDecorator {
		    public WhipDecorator(Coffee coffee) {
		        super(coffee);
		    }
		    @Override
		    public double getCost() {
		        return super.getCost() + 3.50;
		    }
		    @Override
		    public String getDescription() {
		        return super.getDescription() + ", Whip";
		    }
		}
	```

5. 使用

	```java
		public class CoffeeShop {
		    public static void main(String[] args) {
		        // 1. 点一杯基础浓缩咖啡
		        Coffee myCoffee = new Espresso();
		        System.out.println("Order: " + myCoffee.getDescription() + " Cost: $" + myCoffee.getCost());
		        // 输出: Order: Espresso Cost: $1.99
		
		        // 2. 动态添加牛奶和摩卡装饰 (运行时组合功能!)
		        myCoffee = new MilkDecorator(myCoffee); // 用牛奶装饰原来的Espresso
		        myCoffee = new MochaDecorator(myCoffee); // 再用摩卡装饰现在已包含牛奶的Espresso
		
		        System.out.println("Order: " + myCoffee.getDescription() + " Cost: $" + myCoffee.getCost());
		        // 输出: Order: Espresso, Milk, Mocha Cost: $3.19 (1.99 + 0.50 + 0.70)
		
		        // 3. 再给上面的咖啡加奶油 (继续动态添加!)
		        myCoffee = new WhipDecorator(myCoffee);
		        System.out.println("Order: " + myCoffee.getDescription() + " Cost: $" + myCoffee.getCost());
		        // 输出: Order: Espresso, Milk, Mocha, Whip Cost: $3.59 (3.19 + 0.40)
		
		        // 4. 直接点一杯加了牛奶的拿铁 (组合方式自由!)
		        Coffee fancyCoffee = new WhipDecorator(new MochaDecorator(new Latte()));
		        System.out.println("Order: " + fancyCoffee.getDescription() + " Cost: $" + fancyCoffee.getCost());
		        // 输出: Order: Latte, Mocha, Whip Cost: $3.59 (2.49 + 0.70 + 0.40)
		    }
		}
		
	```

## 关键理解

- 并没有创建出双倍咖啡拿铁、加奶拿铁等类。
- 将拿铁对象传给了牛奶装饰器、奶油装饰器的构造函数，一层层进行包裹装饰
- 最终的对象 `myCoffee` 仍然是一个 `Coffee` 类型

# 业务场景

用于需要多个功能灵活的进行各种组合的场景，举些例子：
- **API 安全防护链：**
	- 每个请求在执行正式的业务之前可能要经过一些安全检查或处理
	- 不同的API端点（Endpoint）可能需要不同的组合。比如 `/public/data` 可能只需要基础验证和日志，而 `/user/profile` 则需要所有步骤。
	- 安全需求可能会变化，需要方便地添加、移除或调整处理步骤的顺序。
- **商品价格计算引擎**
	- 基础商品价格（Base Price）叠加多种促销活动，`满减（DiscountOff）`、`折扣（DiscountRate）`、`包邮（FreeShipping）`、`优惠券（Coupon）`、`会员价（MemberPrice）`等
	- 促销活动可以独立开启与关闭，可以任意组合
	- 活动规则可能经常变化
	- 计算最终价格时需要清晰地知道每一步的优惠明细
- **数据流处理管道**
	- 需要处理来自不同来源（文件、Kafka、Socket）的数据流。
	- 数据需要经过一系列处理步骤：格式转换、数据清洗、文件下载、解码、压缩等操作
