# 概述

工厂模式是创建型设计模式，它**将对象的创建过程封装起来**，使客户端代码无需关心具体实现细节。工厂模式的核心思想是通过一个"工厂"来创建对象，而不是直接使用`new`操作符实例化具体类。

工厂设计模式的主要优势有：
- 解耦：将对象创建与使用分离
- 可扩展：轻松添加新产品类型
- **代码复用**：集中管理对象创建逻辑
- **符合开闭原则**：对扩展开放，对修改关闭

工厂模式的三种类型：
- 简单工厂模式
- 工厂方法模式
- 抽象工厂模式

# 简单工厂模式

简单工厂模式，顾名思义，是最简单的工厂模式。它由一个**工厂类**组成，这个工厂类拥有一个静态方法（或非静态方法），根据传入的**参数**来判断并创建不同类的实例。

你可以把它想象成一个“代工厂”，你告诉它你需要什么，它就直接给你生产出来。

组成部分：
- **工厂类 (Factory)**：负责实现创建所有产品实例的逻辑。它通常有一个静态的创建方法。
- **抽象产品 (Abstract Product)**：定义所有产品都应该遵循的接口或抽象类。
- **具体产品 (Concrete Product)**：实现抽象产品接口，是工厂实际创建的对象。。

## 举个🌰：

```java
// 支付接口
interface Payment {
    void pay(double amount);
}

// 具体支付实现
class Alipay implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("使用支付宝支付: ¥" + amount);
    }
}

class WechatPay implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("使用微信支付: ¥" + amount);
    }
}

class BankCardPay implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("使用银行卡支付: ¥" + amount);
    }
}

// 简单支付工厂
class PaymentFactory {
    public static Payment createPayment(String type) {
        switch (type.toLowerCase()) {
            case "alipay": return new Alipay();
            case "wechat": return new WechatPay();
            case "bankcard": return new BankCardPay();
            default: throw new IllegalArgumentException("不支持的支付方式");
        }
    }
}

// 客户端使用
public class Client {
    public static void main(String[] args) {
        Payment payment = PaymentFactory.createPayment("alipay");
        payment.pay(100.0);
    }
}
```

- 抽取公共接口 `Payment`  
- 编写多种支付实现：`Alipay` `WechatPay` `BankCardPay`
- 编写支付方式工厂 `PaymentFactory` 通过传入的类型 `new` 出来支付类返回抽象
- 使用时多态特性，父类引用指向子类对象， 通过工厂与类型创建抽象类 `Payment payment = PaymentFactory.createPayment("alipay");`

## 适用场景
- 对象创建逻辑简单    
- 产品类型有限且不常变化    
- 需要快速实现解耦    

## 缺点
违反开闭原则，添加新产品需要修改工厂类。

# 工厂方法模式

工厂方法模式是对简单工厂模式的改进。它将**产品创建的职责**从一个集中的工厂类**下放**到各个**具体工厂类**中。每个具体产品都对应一个具体的工厂类，由该工厂类来创建它自己的产品。

## 组成部分：
- **抽象产品 (Abstract Product)**：定义所有产品都应该遵循的接口或抽象类。
- **具体产品 (Concrete Product)**：实现抽象产品接口，是具体工厂创建的对象。
- **抽象工厂 (Abstract Factory)**：定义一个创建产品对象的抽象方法。
- **具体工厂 (Concrete Factory)**：实现抽象工厂接口，负责创建具体产品实例。每个具体工厂只生产一种具体产品。

## 举个🌰
- 假设我们正在开发一个电商平台，需要处理：
	- **商品管理**：创建不同类型的商品（实物商品、电子卡券、服务类商品）
	- **订单处理**：处理不同类型的订单（普通订单、预售订单）


1. 定义商品抽象接口
	```java
		public interface Product {  
		  
		    // 显示商品信息  
		    void displayInfo();  
		  
		    // 验证商品信息  
		    void validate();  
		}
	```

2. 编写具体的商品实现，如实物商品、电子卡券、服务类商品
	```java
		  
		// 2. 具体商品实现
		class PhysicalProduct implements Product {
		    @Override
		    public void displayInfo() {
		        System.out.println("实物商品：需要物流配送");
		    }
		    
		    @Override
		    public void validate() {
		        System.out.println("验证实物商品库存和配送地址");
		    }
		}
		
		class DigitalProduct implements Product {
		    @Override
		    public void displayInfo() {
		        System.out.println("电子卡券：发送兑换码到邮箱");
		    }
		    
		    @Override
		    public void validate() {
		        System.out.println("验证电子卡券有效期");
		    }
		}
		
		class ServiceProduct implements Product {
		    @Override
		    public void displayInfo() {
		        System.out.println("服务类商品：预约服务时间");
		    }
		    
		    @Override
		    public void validate() {
		        System.out.println("验证服务提供商可用性");
		    }
		}
	```

3.  工厂方法模式核心：定义创建工厂接口
	```java
		interface ProductFactory {
		    Product createProduct();
		}
	```

4. 具体工厂实现
	```java
		// 实物商品工厂
		class PhysicalProductFactory implements ProductFactory {
			@Override
			public Product createProduct() {
				return new PhysicalProduct();
			}
		}
	
		// 电子卡券商品工厂
		class DigitalProductFactory implements ProductFactory {
			@Override
			public Product createProduct() {
				return new DigitalProduct();
			}
		}
	// 服务商品工厂
		class ServiceProductFactory implements ProductFactory {
			@Override
			public Product createProduct() {
				return new ServiceProduct();
			}
		}
	```

5. 使用

	```java
		public class ProductManager {
			public static void main(String[] args) {
				// 根据业务需求选择工厂
				ProductFactory factory = getProductFactory("digital");
				
				// 使用工厂创建产品
				Product product = factory.createProduct();
				
				// 使用产品
				product.displayInfo();
				product.validate();
			}
			
			private static ProductFactory getProductFactory(String type) {
				switch (type) {
					case "physical": return new PhysicalProductFactory();
					case "digital": return new DigitalProductFactory();
					case "service": return new ServiceProductFactory();
					default: throw new IllegalArgumentException("未知商品类型");
				}
			}
		}
	```

> 工厂方法模式特点：

6. 单一产品创建：一个工厂只负责创建一种产品
7. 扩展方便：添加新商品类型只需要新增工厂和产品类
8. 整体替换：切换工厂即可切换整个产品系列

## 适用场景

- **当一个类不能预料它需要创建哪个类的对象时。**
- **当类希望将其创建对象的职责延迟到其子类时。**
- **系统需要增加新的产品种类时，无需修改现有代码，只需增加新的具体产品类和对应的具体工厂类。** 这是它相比简单工厂模式最大的优势，符合**开闭原则**。

## 缺点

- **类的数量会增加**：每增加一种产品，就需要增加一个具体工厂类，导致类的数量膨胀

# 抽象工厂模式

抽象工厂模式是工厂方法模式的进一步抽象和推广。它提供一个**接口**（或抽象类），用于创建**一系列相关或相互依赖的对象**，而无需指定它们具体的类。

## 组成部分
- 抽象工厂：一个接口或抽象类，声明创建一组产品的方法
- 具体工厂：实现抽象工厂的接口，负责创建具体产品族中的产品。每个具体工厂对应一个产品系列。
- 抽象产品：一组接口或抽象类，声明了产品的方法。每个抽象产品对应一个产品族中的一个产品类型。
- 具体产品：实现抽象产品接口，是抽象工厂模式最终创建的对象。


## 举个🌰

```java
	// ------ 产品族A：交通工具 ------
	interface Vehicle {
		void move();
	}
	
	class Car implements Vehicle {
		public void move() { System.out.println("汽车行驶"); }
	}
	
	class Ship implements Vehicle {
		public void move() { System.out.println("轮船航行"); }
	}
	
	// ------ 产品族B：武器 ------
	interface Weapon {
		void attack();
	}
	
	class Pistol implements Weapon {
		public void attack() { System.out.println("手枪射击"); }
	}
	
	class Cannon implements Weapon {
		public void attack() { System.out.println("大炮开火"); }
	}
	
	// ------ 抽象工厂（定义产品族） ------
	interface MilitaryFactory {
		Vehicle createVehicle();
		Weapon createWeapon();
	}
	
	// ------ 具体工厂1：陆军装备族 ------
	class ArmyFactory implements MilitaryFactory {
		public Vehicle createVehicle() { return new Car(); }
		public Weapon createWeapon() { return new Pistol(); }
	}
	
	// ------ 具体工厂2：海军装备族 ------
	class NavyFactory implements MilitaryFactory {
		public Vehicle createVehicle() { return new Ship(); }
		public Weapon createWeapon() { return new Cannon(); }
	}
	
	// 客户端使用
	public class Client {
		public static void main(String[] args) {
			MilitaryFactory factory = new NavyFactory(); // 切换工厂即可切换整个产品族
			
			Vehicle vehicle = factory.createVehicle(); // 创建轮船
			Weapon weapon = factory.createWeapon();    // 创建大炮
			
			vehicle.move();
			weapon.attack();
		}
	}
```



# 工厂方法模式与抽象工厂对比

通过上述案例能够总结出一些工厂方法与抽象工厂之间的区别：
1. 产品数量
	- 工厂方法：1个工厂只能创建1种产品
	- 抽象工厂：1个工厂可以创建1组关联的产品
2. 扩展方向
	- 工厂方法：新增产品类型时，需要新建工厂、新建产品
	- 抽象工厂：新增产品族时，需要实现抽象工厂的组合（飞机+导弹）
3. 设计复杂度
	- 工厂方法：适合产品结构简单的场景
	- 抽象工厂：适合产品有强关联的场景（如游戏装备套装）



# 总结：实际上的业务场景

- **接入多模式的文件上传**：
	- 系统需要支持上传文件到不同存储后端（本地磁盘、阿里云OSS、腾讯云COS、AWS S3、MinIO、FTP服务器等）。
- **接入多平台的短信发送**
	- 需要接入多个短信服务商（阿里云短信、腾讯云短信、容联云通讯、云片、Nexmo等），根据配置、成本或成功率动态选择或备用切换。
- **接入多的支付渠道选择**
	- 电商平台需要接入多种支付方式（支付宝App支付、支付宝网页支付、微信App支付、微信JSAPI支付、微信Native支付、银联支付、PayPal、Stripe等）
- **报表导出**
	- 系统需要将数据导出为不同格式（Excel、PDF、CSV、Word、HTML）
- **通知/消息推送**
	- 系统需要向用户发送通知，通知可以通过多种渠道送达（站内信、Email、App推送、微信模板消息、短信）。一个重要的通知可能需要同时通过多个渠道发送（比如订单支付成功同时发App推送和Email）。
- **规则引擎/策略模式中的策略创建**
	- 使用策略模式实现不同的业务规则（如折扣计算规则：新用户折扣、会员等级折扣、满减折扣、促销活动折扣）。策略对象本身可能需要根据配置或条件动态创建。

**总结与选择建议：**

- **工厂方法 (Factory Method)：** 当你 **“需要创建什么？”** 的问题在运行时才能确定，并且你只需要创建 **一种类型** 的对象（尽管这种类型有多个变体）时使用。它隔离了创建者（调用工厂的代码）和具体产品。你想到的文件上传、短信发送、支付渠道(简单场景)、报表导出、规则策略创建都是典型的工厂方法应用。
    
- **抽象工厂 (Abstract Factory)：** 当你 **“需要创建哪些相关对象？”** 的问题在运行时才能确定，并且你需要创建 **一系列/一组** 相互关联或依赖的对象（一个产品族）时使用。它强调的是这些对象的**兼容性**和**整体替换**。支付渠道(复杂场景，含验证、查询、退款)、数据库方言工具集、通知策略(多渠道组合)是典型的抽象工厂应用。
