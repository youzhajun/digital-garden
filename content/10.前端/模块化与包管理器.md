# 前端模块化的历史由来

为了解决全局变量环境污染与各个模块间混乱的依赖关系的问题。

前端发展历史：

- 阶段一： 受限于计算机硬件与前端技术，无模块化
- 阶段二： ajax 的出现使得前端可以实现更多的功能，无模块化
- 阶段三： 2008年谷歌v8引擎的发布使得js的执行速度推上新台阶。node js出现，但模块化问题还未真正解决。 社区解决方案出现Common JS，nodejs首先支持.
- 阶段四：浏览器层面开始支持模块化，AMD → CMD → 。。。 → 官方 ES6 标准

# Common JS

common js 是 nodejs 中模块化的解决方案。因为运行在 nodejs 环境中，所以前提要先安装node。

## node 安装

步骤：略

> 备注点：

nodejs 遵循了EcmaScript标准，但由于脱离了浏览器环境，因此：

- 可以在nodejs环境中使用es的任何语法与api
- 但不能在nodejs环境中使用web api

## 规范

在学习common js 之前，首先认识两个重要的概念：模块的导出、模块的导入

任何一个正常的模块化标准，都应该默认隐藏模块中的所有实现，而通过一些特定的语法或api调用暴露。

`common js` 使用 `exports` 导出模块，使用 `require` 导入模块

- 如果一个js文件中存在 `exports` 或 `require`，该js是一个模块
- 模块内所有的代码均为隐藏代码，包括全局变量，全局函数
- 如果模块需要暴露出一些 API 供外部使用，则需要 `exports` 导出，`exports` 是一个空对象
- 如果一个模块需要导入其他模块的 API，通过 `requrie` 实现，`requrie` 是一个函数，函数需要传入导入模块的文件路径 并返回给一个对象

导出实例代码：

```jsx
let index = 0

function getNum() {
  index++
  return index
}

// 导出 exports 相当于是 {} 空对象
exports.getNum = getNum
exports.testName = 'zhangSan'
```

导入实例代码：

```jsx
// 导入require 相当于函数， 函数会有一个返回值，返回值 相当于 exports 这个对象
const data = require('./utils')
console.log(data.getNum())
```

**备注：`commonjs` 只是提供了模块化的一种规范，并没有告知如何去实现，nodejs为了实现该规范做以下处理**

## nodejs对 CommonJs 的实现

1. 为了保证效率，仅加载必要模块，`nodejs` 只有执行到 `requrie` 函数时才会执行该模块
    
2. 为了隐藏模块中的内容，`nodejs` 在执行模块时会将所有的代码放置到一个函数中执行，可以将其理解为立即执行函数，保证不会污染全局
    
3. 为了保证模块的导出，`nodejs` 做了以下处理
    
    1. 在模块开始执行前，初始化一个值 `module.exports = {}` , 该值就为导出的对象
    2. 为了方便开发者导出，`nodejs` 又声明了一个变量 `exports = module.exports`
    
    ```jsx
    (function(module){
    	module.exports = {}
    	var exports = module.exports
    	// 逻辑代码
    	
    	return module.exports
    })()
    ```
    

4 .为了避免反复加载一个模块，nodejs默认开启了模块缓存，如果模块之前已经加载过则会优先使用缓存

# 浏览器模块化

## 难题

为什么浏览器没有去实现 common js？

可以理解为 commonjs 的执行过程是同步的（先读取文件，再将内容放到函数中执行返回导出内容）。但是！到了浏览器端就会出现严重的问题

- 浏览器加载 js 文件是从网络中获取的，网络状况不可保证，读取文件效率低下，并且common js 是同步的，极大的降低性能
- 如果需要解决上述问题，就需要将读取js文件内容将其放到一个环境中执行，这需要浏览器厂商进行开发，但是commonjs 只是个社区规范而非官方标准，浏览器厂商不愿意支持。

新的规范的原理简单解释：

- 远程同步加载js慢，做成异步即可，异步执行后返回一个回调
- 编写模块时直接放到函数中

## 解决方案1： AMD 模块化

AMD**（Asynchronous Module Definition）**

- **定义**：由 **RequireJS** 推广，核心是**异步加载模块**，依赖前置且提前执行。
    
- **特点**：
    
    - **依赖前置**：模块定义时需显式声明所有依赖（数组形式），依赖模块**提前下载并执行**。
        
    - **适合浏览器**：通过异步并行加载依赖，减少阻塞，提升性能。
        
    - **语法示例**：
        
        ```jsx
        define(['dep1', 'dep2'], function (dep1, dep2) {
          // 模块逻辑
          return moduleExports;
        });
        
        ```
        
- **优点**：
    
    - 依赖预加载，执行顺序清晰，适合复杂依赖关系。
    - 并行加载提升性能，尤其适合大型项目。
- **缺点**：
    
    - 依赖声明冗余，模块较多时维护成本高。
    - 提前执行可能占用更多内存（未使用的模块也被执行）。

---

## 解决方案2：CMD 模块化

**CMD（Common Module Definition）**

- **定义**：由 **SeaJS** 推广，强调**按需加载**，依赖就近且延迟执行。
    
- **特点**：
    
    - **依赖就近**：在代码中通过 `require` **按需引入依赖**，依赖模块**使用时才执行**。
        
    - **语法接近 CommonJS**：写法类似 Node.js，便于迁移。
        
    - **语法示例**：
        
        ```jsx
        define(function (require, exports, module) {
          var dep1 = require('dep1'); // 按需引入
          var dep2 = require('dep2');
          exports.something = function () { /* ... */ };
        });
        
        ```
        
- **优点**：
    
    - 代码更直观，符合“用时加载”的直觉。
    - 减少不必要的资源占用（未执行的模块不加载）。
- **缺点**：
    
    - 依赖延迟执行可能导致逻辑分散，调试复杂度增加。
    - 执行时机不确定，可能影响性能优化。

---

随着 **ES6 模块标准**的普及（通过 `import/export` 语法），AMD 和 CMD 逐渐被原生模块化方案取代。现代工具（如 Webpack、Rollup）在底层兼容多种模块规范，最终打包为浏览器支持的格式。但理解 AMD/CMD 仍有助于掌握模块化演进的历史和设计思想。

**建议**：新项目优先使用 ES6 模块，旧项目按原有规范维护。若需兼容旧环境，可通过工具转换。

## 官方解决方案：ES6 模块化

2015年，随着ES6发布了官方的模块化标准，后成为ES6模块化，有以下特点：

- 使用依赖**预声明**的方式导入模块（有助于阅读，更明确依赖关系）
- 灵活的多种导入导出
- 规范的路径表示法

### 模块的入口

注意：这一部分非模块化标准，而是浏览器厂商的实现

```jsx
<script src='主文件入口' type='module'/>
```

ES6中的导入导出分为两种：

- 基本导入导出
- 默认导入导出

### 基本导出导入

**导出：**

语法1，使用声明表达式：

```jsx
export 声明语句

// 举个例子：

// 导出名字为a， 值为1
export var a = 1 
// 导出名字为test，值为函数
export function test(){
	console.log('test')
}
```

语法2，使用：

```jsx
export {具名符号}

// 举个例子
const age = 18
const name = 'zhangsan'
export {name, age} // 將age变量的名称作为 导出的名称， 将age变量的值，作为导出的值
```

---

**导入**

因为ES6模块化使用依赖**预声明**的方式，所以所有导入的内容都要写到代码之前。基本导入语法如下：

```jsx
import {导入的符号列表，英文逗号分割} from '模块路径'
```

细节：

- 导入时可以通过关键字 `as` 对导入的内容重命名
    
- **导入后的内容为常量，不可以修改**！
    
- 可以使用 * 导入导出模块所有导出的内容，必须要重命名，所有的导出的内容会组成一个对象。
    
    ```jsx
    import * as obj from './test.js'
    ```
    
- 只运行模块，不使用他内部的任何导出(初始化时做某些操作)
    
    ```jsx
    import './test.js'
    ```
    

---

### 默认导出导入

每一个模块除了允许有多个基本导出之外，还允许一个默认导出

默认导出类似于Common js 中的module.exports，由于只有1个因此不用起名。具体语法：

```jsx
export default 默认导出的数据
```

导入语法：

```jsx
import obj from './test.js'  // 将test.js 中的默认导出内容 放到 obj 中
```

当一个模块既有默认导出也有基本导出时，使用*导入会将所有的默认、基本导出都进行导入到一个对象中，默认导出的内容会赋值到导出对象的 default 属性中。

```jsx
import * as obj from './test.js'
console.log(obj.default)
```

当有选择的导入基本导出内容并且又要导入默认导出的内容时：

```jsx
import data, {a, b} from './test.js'
```

### ES6 模块化中的其他细节

1. 导出时尽量导出不可变的值
2. 可以使用无绑定的导入用于执行一些初始化的代码
3. 可以使用绑定再导出，来重新导出来自另一个模块的内容（utils导入了utilsA,utilsB模块的内容，然后utils再将其导出）

3. 编写ui模块，绘制元素
    
    ```jsx
    import * as map from './map.js'
    // 用于将地图显示到页面上
    const mapContainer = document.getElementById('game')
    
    const pieceWidth = 45
    const pieceHeight = 45
    /**
     * 用于显示地图
     */
    export default function show() {
      // 1. 设置div 的宽高
      setDivContainer()
      // 2. 显示地图中的内容
      setContent()
    }
    
    function setDivContainer() {
      mapContainer.style.width = map.colNumber * pieceWidth + 'px'
      mapContainer.style.height = map.rowNumber * pieceHeight + 'px'
    }
    
    function setContent() {
      // 1. 清空容器
      mapContainer.innerHTML = ''
      // 2. 遍历地图中的内容，将内容添加到div中
      for (let row = 0; row < map.rowNumber; row++) {
        for (let col = 0; col < map.colNumber; col++) {
          setOnePiece(row, col)
        }
      }
    }
    
    function setOnePiece(row, col) {
      const value = map.content[row][col]
      const correct = isCorrect(row, col)
    
      const div = document.createElement('div')
      div.className = 'item'
      // 调整div的位置
      div.style.left = col * pieceWidth + 'px'
      div.style.top = row * pieceHeight + 'px'
      mapContainer.appendChild(div)
    
      if (map.BOX === value) {
        div.classList.add('box')
        // 当前位置是正确位置吗?
        if (correct) {
          div.classList.add('correct-box')
        }
      } else if (map.PLAYER === value) {
        div.classList.add('player')
      } else if (map.WALL === value) {
        div.classList.add('wall')
      } else {
        if (correct) {
          div.classList.add('correct')
        }
      }
    }
    
    function isCorrect(row, col) {
      // 判断是否是正确位置
      return map.correct.find((i) => i.row === row && i.col === col) !== undefined
    }
    ```
    
4. 编写角色移动功能
    
    ```jsx
    import * as map from './map.js'
    
    /**
     * 玩家移动
     * @param {方向} direction left right up down
     */
    export function playerMove(direction) {
      const palyPoint = getPlayerPosition()
      const nextInfo = getPlayerNextInfo(palyPoint.row, palyPoint.col, direction)
      if (nextInfo.next === map.WALL) {
        console.log('撞墙啦')
        return false
      } else if (nextInfo.next === map.SPACE) {
        exchange(palyPoint, nextInfo)
        return true
      } else if (nextInfo.next === map.BOX) {
        // 下一个位置是箱子
        const boxNextInfo = getPlayerNextInfo(nextInfo.row, nextInfo.col, direction)
        if (boxNextInfo.next === map.SPACE) {
          // 先交换箱子与箱子的下一个位置
          exchange(nextInfo, boxNextInfo)
          // 在交换角色与箱子的位置
          exchange(palyPoint, nextInfo)
          return true
        } else {
          console.log('箱子没办法移动')
          return false
        }
      }
    }
    
    /**
     * 获取玩家位置
     * @returns
     */
    function getPlayerPosition() {
      // 1. 获取玩家当前位置
      for (let row = 0; row < map.rowNumber; row++) {
        for (let col = 0; col < map.colNumber; col++) {
          if (map.content[row][col] === map.PLAYER) {
            return {
              row,
              col
            }
          }
        }
      }
    }
    
    /**
     * 获取下一步信息
     * @param {指定行} row
     * @param {指定列} col
     * @param {方向} direction
     */
    function getPlayerNextInfo(row, col, direction) {
      if (direction === 'left') {
        col--
      } else if (direction === 'right') {
        col++
      } else if (direction === 'up') {
        row--
      } else if (direction === 'down') {
        row++
      } else {
        alert('方向错误')
      }
      return {
        row,
        col,
        next: map.content[row][col]
      }
    }
    
    /**
     * 位置交换
     * @param {位置1} point1
     * @param {位置2} point2
     */
    function exchange(point1, point2) {
      const temp = map.content[point1.row][point1.col]
      map.content[point1.row][point1.col] = map.content[point2.row][point2.col]
      map.content[point2.row][point2.col] = temp
    }
    
    /**
     * 判断是否游戏胜利
     * @returns
     */
    export function isWin() {
      for (let i = 0; i < map.correct.length; i++) {
        const point = map.correct[i]
        if (map.content[point.row][point.col] !== map.BOX) {
          return false
        }
      }
      return true
    }
    
    ```

# 包管理器的由来

在 Web 前端发展的早期阶段（如 jQuery 时代），开发者需要手动管理 JavaScript 依赖库（例如下载 `.js` 文件并引入到 HTML 中）。随着前端工程复杂度的提升，这种方式逐渐暴露出以下问题：

1. **依赖管理困难：**
    1. **手动维护依赖版本易导致冲突（如全局变量污染、版本不兼容）**
2. **模块化需求：**
    1. **CommonJS、ES Modules 等模块化规范普及后，需要工具管理模块间的依赖关系。**
3. **工程化需求**

目前前端流行的包管理工具有：npm、yarn、pnpm

# NPM

**诞生背景**：Node.js 官方工具，随 Node.js 安装自动提供。

- npm 常用命令

```bash
npm init          # 初始化项目
npm install       # 安装所有依赖（缩写 npm i）
npm install lodash --save     # 安装生产依赖
npm install eslint --save-dev # 安装开发依赖
npm update        # 更新依赖
npm uninstall lodash # 移除依赖
```

- npm 其他命令

```powershell
npm root    // 查看安装目录
npm root -g   // 查看全局安装目录

npm uninstall [-g] 包名 // 卸载包

npm confing ls [--json]  // 列出所有生效的配置
npm config get 配置项目名  // 得到某一项配置
npm config set 配置项目名  // 设置某一项配置

npm login // 登录
npm whoami //
npm loginout // 注销
```

• **诞生背景**：Facebook 团队为解决 npm 早期版本的速度和安全性问题而开发。

```bash
yarn init         # 初始化项目
yarn              # 安装所有依赖（等价于 yarn install）
yarn add lodash   # 安装生产依赖
yarn add eslint -D # 安装开发依赖
yarn upgrade      # 更新依赖
yarn remove lodash # 移除依赖
yarn workspace    # Monorepo 支持
```


# PNPM

- **诞生背景**：解决 npm/Yarn 的磁盘空间浪费问题，通过硬链接和符号链接优化存储。

```bash
pnpm init         # 初始化项目
pnpm install      # 安装所有依赖（缩写 pnpm i）
pnpm add lodash   # 安装生产依赖
pnpm add eslint -D # 安装开发依赖
pnpm update       # 更新依赖
pnpm remove lodash # 移除依赖
pnpm store prune  # 清理全局存储
```

> 🛤️ `node` 环境中如何获取系统环境变量？ 如何在启动脚本中指定环境变量

`node` 中定义了个全局变量 `global` , `global.process.ENV` 可获取所有环境变量

通过 cross-env 库可以跨平台使用一条命令设置环境变量，`cross-env NODE_ENV=test`。

```bash
npm i -D cross-env

"scripts": {
  "test": "cross-env NODE_ENV=test node index.js"
}

console.log(process.env.NODE_ENV)
```
