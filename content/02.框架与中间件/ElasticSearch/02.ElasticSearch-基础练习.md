- 搭建好的 `es` 服务


## 基础查询
查询的基本结构：
- `es` 中的查询条件是 `json` 格式
- `json` 中的 `query` 上下文，这是定义要查找哪些文档以及如何评分（相关性排序）的核心部分。

### 全文检索
适用于 `text` 类型的字段，会经过分析器处理。

**`match`:** 最常用的全文查询。查询字符串会被分析（分词），然后生成一个布尔查询来匹配文档。支持模糊匹配、短语匹配（`match_phrase`）、短语前缀匹配（`match_phrase_prefix`）等变种。

```json

{
  "query": {
	"match_all": {}   // 查询全部数据
  }
}
```

-  查询 `name` 字段中带有 `ge` 的数据。 比如：`liu ge`、 `li ge`。可以理解为 `like`

	```json
	{
	  "query": {
	    "match": {
	      "name": "ge"  
	    }
	  }
	}
	```

- 查询 `name` 字段中带有 `ge` 或 `liu` 的数据。 比如： `liu ge`、 `li ge` 、 `xiao liu`。`ge` 与 `liu` 的 `like` 取的是**或**关系。

	```json
	{
	  "query": {
	    "match": {
	      "name": "ge liu"  
	    }
	  }
	}
	```

**`multi_match`:** 在多个字段上执行相同的 `match` 查询。比如说，我既想在 `name` 字段上查询带有 `liu` 的数据还想在 `hobby` 字段查询带有`liu`的数据。
```json
{
  "query": {
    "multi_match": {
      "query": "liu",
      "fields": ["name", "hobby"]
    }
  }
}
```

### 词项级查询

适用于 `keyword`, `numeric`, `date`, `boolean` 等未分析（或精确值）的字段。用于精确匹配、范围查找等。**不参与相关性评分（或评分恒定），常用于过滤**

- **`term`:** 精确匹配字段中的某个词项（未经分析）。用于 `keyword` 或数值/日期等。
	```json
		{
		  "query": {
		    "term": {
		      "age": 17 // 精确匹配 age 字段值为 17 的文档
		    }
		  }
		}
	```
- **`terms`:** 匹配字段中包含指定数组中**任意一个**词项的文档。
	```json
		{
		  "query": {
		    "terms": {
		      "age": [17, 18, 19] // 精确匹配 age 字段值为 17\18\19 的文档
		    }
		  }
		}

	```
- **`range`:** 匹配字段值在指定范围内的文档。`gt` 大于、 `lt` 小于 
	```json
		{
		  "query": {
		    "range": {
		      "gte": 17,
		      "lte": 20
		    }
		  }
		}
	```
- **`exists`:** 匹配包含指定字段（且该字段值不为 `null` 或空数组）的文档。理解为 `in`
	```json
		{
		  "query": {
		    "exists": {
		      "name": "zhangsan"
		    }
		  }
		}
	```
- **`prefix` / `wildcard` / `regexp`:** 基于前缀、通配符（`*` 匹配任意字符序列, `?` 匹配单个字符）或正则表达式进行匹配。**性能开销较大，慎用，尤其避免前缀通配符开头 (`a*b` 比 `abc*` 慢很多)**  略。后期用到了再补充。

## 复杂查询

- **`bool` 查询 (最重要的复合查询)：** 组合多个子查询，使用以下逻辑子句：
	-  **`must` (AND):** 子句**必须**匹配。贡献相关性得分。
	- **`filter` (AND):** 子句**必须**匹配。**不**贡献相关性得分（评分被忽略或计为 0）。**强烈推荐用于过滤条件（状态、时间范围、类别等），因为它可以利用缓存且不影响排序**。
	- **`should` (OR):** 子句**应该**匹配。在 `must` 或 `filter` 不存在时，默认至少匹配一个 `should` 子句（可通过 `minimum_should_match` 参数调整）。匹配的 `should` 子句越多，文档得分越高（通常）。
	- **`must_not` (NOT):** 子句**必须不**匹配。在 `filter` 上下文中执行（不评分）

#### 查询 name 带有 log 的数据
```shell
	GET /products_practice/_search
	{	
	  "query": {	
	    "wildcard": {	
	      "name.keyword": {	
	        "value": "*Log*",	
	         "case_insensitive": true	
	      }	
	    }	
	  }	
	}
```

- `wildcard`：   基于通配符进行匹配，用于模糊匹配。用法如上，需要`value`中填写查询的内容

#### 查询 `category` 为 `"ETL"` 且 `released` 年份大于等于 2011
```shell
	GET /products_practice/_search
	{
	  "query": {
	    "bool": {
	      "must": [
	        {
	          "term": {
	            "category": "ETL"
	          }
	        },
	        {
	          "range": {
	            "released": {
	              "gte": "2011"
	            }
	          }
	        }
	      ]
	    }
	  }
	}
```

- 多个条件使用 `bool.must` 表示 `and`
- `term` 用于精确匹配不分词的字段
- `range.get` 数值或日期的范围查询，`gte` 表示大于等于

#### 查询价格大于50的产品
```shell
	GET /products_practice/_search
	{
	  "query": {
	    "range": {
	      "price": {
	        "gte": 50
	      }
	    }
	  }
	}
```


#### 前缀匹配 name 以 Log 开头的文档？
```shell
	GET /products_practice/_search

	{
	  "query": {
	    "prefix": {
	      "name.keyword": {
	        "value": "Log"
	      }
	    }
	  }
	}
```

- `prefix` 用于前缀匹配，`value` 不需要加通配符。

#### 查找没有 category 字段的文档？
```shell
	GET /products_practice/_search

	{
	  "query": {
	    "bool": {
	      "must_not": {
	        "exists": {
	          "field": "category"
	        }
	      }
	    }
	  }
	}
```

- `exists.field`： 判断是否存在某个字段
- `bool.must_not`： 查询条件的否定，!=
