# 是什么
`Elasticsearch` 是一个基于 `Apache Lucene` 构建的**分布式搜索引擎**，具有以下特性：
- 全文搜索能力强（基于倒排索引）
- 实时搜索（`Near Real-Time，NRT`）
- 支持分布式存储与高可用架构
- 支持 `RESTful API` 操作
- 可用于日志分析、复杂查询、聚合分析等场景
# 能做什么？
实际开发中主要用于搜索相关的功能。

| 场景       | 示例应用                |
| -------- | ------------------- |
| 全文搜索     | 电商商品搜索、博客内容检索       |
| 日志检索     | 系统日志、业务日志收集与分析（ELK） |
| 数据聚合分析   | 用户行为分析、运营报表         |
| 实时推荐与个性化 | 新闻推荐、视频推荐           |
| 地理位置查询   | 地图附近商家搜索、位置打卡系统     |

# docker 安装

`docker` 需要启动两个容器，`Elasticsearch` 和 `Kibana`（控制面板），此处采用的 `docker compose` 的方式。
1. 编写 `componse`
	```yaml
	version: '3.8'

	services:
	  elasticsearch:
		image: docker.elastic.co/elasticsearch/elasticsearch:8.13.0
		container_name: es8
		environment:
		  - discovery.type=single-node
		  - xpack.security.enabled=true
		  - xpack.security.transport.ssl.enabled=true
		  # 关闭ssl简化配置
		  - xpack.security.http.ssl.enabled=false
		  - ELASTIC_PASSWORD=elastic123
		  - "ES_JAVA_OPTS=-Xms1g -Xmx1g"
		ports:
		  - "9200:9200"
		volumes:
		  - esdata:/usr/share/elasticsearch/data
		networks:
		  - esnet
	
	  kibana:
		image: docker.elastic.co/kibana/kibana:8.13.0
		container_name: kibana8
		environment:
		  - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
		  - ELASTICSEARCH_USERNAME=elastic
		  - ELASTICSEARCH_PASSWORD=elastic123
		ports:
		  - "5601:5601"
		depends_on:
		  - elasticsearch
		networks:
		  - esnet
	
	volumes:
	  esdata:
	
	networks:
	  esnet:
	
	```

2. 后台启动容器

	```bash
		docker-compose up -d
		
		# 查看状态
		docker ps
	```

3. 验证访问
	```bash
		curl -u elastic:elastic123 http://localhost:9200/
	```

4. 访问面板
	```conf
	http://localhost:5601
	elastic / elastic123
	```

# 核心概念

## 索引（index）

可以理解为数据库中的**表**，有以下特点：
- 存储某类文档（数据记录）
- 每个索引有自己的==名称==、==映射（Mapping）==和==配置==
- 一个集群可以包含多个索引

## 文档（document）
文档是 `Elasticsearch` 中的最小存储单元，对应关系型数据库中的“**行**”。
- 每一个文档（行）都已 `json` 格式存储
- 每一个文档（行）必须属于某一个索引（表）
- 每一个文档都有一个唯一的`_id`

## 映射（Mapping）
映射（Mapping）类似于数据库中的“**字段定义**”，定义了字段的**数据类型**和**索引方式**。

| 类型              | 描述             |
| --------------- | -------------- |
| `text`          | 用于全文搜索，支持分词    |
| `keyword`       | 精确匹配（如标签、状态）   |
| date            | 日期字段           |
| `integer\float` | 数值             |
| `boolean`       | 布尔值<br>        |
| `dense_vector`  | 用于向量搜索（8.x 新增） |
## 分片
`elasticsearch` 中的数据都是存储在分片中，索引数据的水平拆分单元。一个索引被分成多个分片。分片分为**主分片**与**副本分片**。
- 主分片：负责写入原始数据。（索引创建时指定主分片的数量`number_of_shards`，单节点环境下1个索引可以配置多个主分片此时数据分散在多个分片上）
- 副本分片：主分片的备份，提升容错性和查询性能。（单节点无法配置副本分片）

> 数据分配机制

当你插入文档时，Elasticsearch 使用如下流程：
1. 取文档的 `_id`
2. 使用哈希算法进行散列
3. 将其映射到某个分片（如：分片 0、1 或 2）
4. 然后写入该分片的存储区域

## 节点与集群
`elasticsearch` 是分布式系统，因此可以部署多个服务搭建分布式集群，单个运行实例称为**节点（Node）**，多个节点协作形成一个**集群（Cluster）**。
- 一个节点可以托管多个索引的多个分片
- 集群通过 `cluster.name` 识别
- 节点通过 `node.name` 标识

节点分别有主节点、数据节点。
- 主节点：负责整个集群的管理工作：如索引创建、节点变动、分片分配、元数据维护等（只做管理，不做处理数据）
- 数据节点：负责实际的数据存储与搜索请求处理（包括读写操作、聚合、排序等）

一个节点可以同时扮演多个角色（默认是主节点 + 数据节点）

# 执行一个查询后ES发生了什么？

1. 解析查询语句：理解用户的`Query DSL`
2. 执行查询：在倒排索引中查询匹配的文档
3. 对每个文档进行评分：对于每个符合查询基本条件的文档，ES 会应用一个或多个评分算法来计算该文档对于_这个特定查询_的相关性得分 (`_score`)。这个过程发生在查询执行的时刻。


# 分词
## 什么是分词

分词是将**连续的文本流**（如一个句子或段落）**分解成独立的、有意义的词元（Tokens）** 的过程。例如：
- 原始文本：`"The quick brown fox jumps!"`    
- 分词结果（可能）：`["the", "quick", "brown", "fox", "jumps"]`    
    - 单词被拆分开。        
    - 标点符号（`!`）被移除。        
    - 大写字母（`The`）转换为小写（`the`）。        
    - 每个独立的词就是一个词元（Token）。
    
## 何时进行分词

分词主要发生在 **两个关键阶段**：
- **索引文档时**
	- **时机：** 将一个文档 `PUT` 或 `POST` 到 `Elasticsearch` 索引时。
	- **对象：** 针对文档中定义为 `text` 类型的字段的内容。
	- **过程：**
		1. ES 根据该字段配置的**分析器（Analyzer）**（包含分词器和过滤器）处理文本。
		2. **分词器（Tokenizer）** 首先将文本拆分成初始的词元流。
		3. **词元过滤器（Token Filters）** 依次对词元进行加工（如转小写、移除停用词、添加同义词、词干还原等）
		4. 最终生成的词元列表被写入该字段的**倒排索引（Inverted Index）** 中。**倒排索引是 ES 快速搜索的核心数据结构，它记录了每个词元出现在哪些文档的哪些字段中**
	- **关键点：** 这个过程是**永久性**的。一旦文档被索引，其 `text` 字段的分词结果就固定存储在倒排索引里。修改分析器设置**不会**自动重新处理已索引的旧文档，需要重建索引（Reindex）
	
- **执行全文检索时**
	- **时机：** 当你使用 **全文查询（Full-text queries）**（如 `match`, `match_phrase`, `multi_match`, `query_string` 等）进行搜索时。
	- **对象：** 针对你输入的**查询字符串（Query String）**。
	- **过程：**    
	    1. ES 需要确定在哪些 `text` 字段上搜索（可能是显式指定，也可能是 `default_field`）。        
	    2. 对于每个目标 `text` 字段：        
	        - ES 默认会使用该字段**索引时配置的同一个分析器**来处理查询字符串。            
	        - 查询字符串经过**相同的分词器（Tokenizer）和词元过滤器（Token Filters）** 处理，生成查询词元（Query Tokens）。            
	    3. 然后，ES 拿着这些查询词元，去对应字段的倒排索引中查找包含这些词元的文档，并根据评分算法计算相关性得分 (`_score`)。
	- **关键点：**
        查询字符串的分词是**临时性**的，仅服务于当前查询。为了确保查询字符串的词元和索引时存储的词元能够匹配上，查询时使用的分析器必须与索引时使用的分析器一致（或兼容）。
## 什么时候不会分词

- **索引 `keyword` 类型字段时：**`keyword` 类型的字段不会进行分词。
- **执行词项级查询（Term-level Queries）时：** 
	- 当使用 `term`, `terms`, `prefix`, `wildcard`, `regexp` 等词项级查询时，你提供的查询值**不会经过分析过程（即不会被分词器或过滤器处理）**。

## 查看分词效果

ES 提供了 `_analyze` API 来测试分词效果，这对于调试和理解分析器行为至关重要：
```shell
	GET /your_index/_analyze
	{
	  "field": "your_text_field_name", // 指定要测试的字段名，ES 会自动使用该字段配置的分析器
	  "text": "The QUICK Brown-Foxes!" // 要分析的文本
	}
```
