# 03-项目实战整合
## 现有项目情况

- 现有项目数据库中有`video`表，表中记录了`id、标题、分类、采集日期、文件地址、作者id、作者名称、来源平台、创建时间`等字段。
- 每天都会消费 `mq` 中消息往 `video` 表中插入数据。
- 前端会根据某些字段进行视频信息的查询。

项目运行一段时间后，随着数据量的增加查询速度越来越慢。

## 目标

- [ ] 引入 `Elasticsearch` 增加搜索效率
- [ ] 同步历史数据到 `Elasticsearch`
- [ ] 保持数据库与 `Elasticsearch` 的数据一致性

## 实现步骤

### 1. `SpringBoot` 整合 `es`

像整合其他框架一样，只需要引入依赖、添加配置即可。
```xml
	<dependency>
	    <groupId>org.springframework.boot</groupId>
	    <artifactId>spring-boot-starter-data-elasticsearch</artifactId>
	</dependency>
```

```yaml
	spring:
	  elasticsearch:
	    uris: http://your-es-host:9200  # 替换成你的ES地址，如果是集群可以配置多个
	    # 如果有用户名和密码
	    # username: your-username
	    # password: your-password
```


### 2. 创建 ES 对应的实体

需要创建一个与ES索引对应的Java类。看上去与 JPA 很像。
```java
	// VideoDocument.java
import org.springframework.data.annotation.Id;
import org.springframework.data.elasticsearch.annotations.*;

import java.util.Date;

@Document(indexName = "video_index") // 指定索引名称
public class VideoDocument {

    @Id // 标记主键
    private Long id;


	// 文本类型，使用IK分词器进行全文检索
    @Field(type = FieldType.Text, analyzer = "ik_max_word", searchAnalyzer = "ik_smart") 
    private String title;

    @Field(type = FieldType.Keyword) // 关键字类型，用于精确匹配和聚合分析
    private String category;

    @Field(type = FieldType.Date, format = DateFormat.date_hour_minute_second) // 日期类型
    private Date collectionDate;

    @Field(type = FieldType.Keyword, index = false) // Keyword类型，但不需要被索引，只做展示
    private String fileUrl;

    @Field(type = FieldType.Long)
    private Long authorId;

    @Field(type = FieldType.Keyword) // 作者名也可用作精确匹配和聚合
    private String authorName;

    @Field(type = FieldType.Keyword)
    private String sourcePlatform;

    @Field(type = FieldType.Date, format = DateFormat.date_hour_minute_second)
    private Date createTime;

    // Getters and Setters ...
}
```

- **`id`**: `@Id`，通常与数据库主键保持一致
- **`title` (标题)**: **`Text`** 类型。最重要的字段，`Text`类型会进行**分词**，支持模糊搜索和全文检索。指定了`ik_max_word`作为分词器（需要安装IK分词器插件）。
- **`category` (分类)**, **`authorName` (作者名称)**, **`sourcePlatform` (来源平台)**: **`Keyword`** 类型。这些字段通常用于**精确匹配**（例如`WHERE category = '科技'`)、**排序**或**聚合**（例如统计每个分类下的视频数量）。`Keyword`类型不分词，作为一个整体进行索引。
- **`collectionDate` (采集日期)**, **`createTime` (创建时间)**: **`Date`** 类型。这允许我们进行高效的日期范围查询（例如查询“最近7天”的视频）。
- **`fileUrl` (文件地址)**: **`Keyword`** 类型，并设置`index = false`。通常不需要根据文件URL来搜索，只需要在结果中返回它。`index = false`意味着这个字段只存储，不创建索引，可以节省空间和提高写入性能

### 3. 整合 ES 后的业务流程

分为**数据写入**、**数据查询**、两条主线。

>数据写入

- 消费 `mq` 数据往数据库写入后，需要进行双写（写入到 `es` 中）
- 当数据**更新**、**删除**时，需要进行双写（写入到`es`中）

举个例子：
```java
	public void handleVideoMessage(VideoDataDTO videoData) {
	 // 1. 将数据转换为数据库实体 
	 Video videoEntity = convertToDbEntity(videoData); 
	 try { 
		 // 2. 写入数据库 (关键步骤，保证数据源的可靠性) 
		 Video savedVideo = videoDbRepository.save(videoEntity); 
		 // 3. 成功写入数据库后，再写入ES 
		 VideoDocument videoDocument = convertToEsDocument(savedVideo); 
		 videoEsRepository.save(videoDocument); 
		 System.out.println("视频 " + savedVideo.getId() + " 已成功同步到数据库和ES。"); 
	 } catch (Exception e) { 
		 // 异常处理：非常重要！ 
		 // - 如果数据库写入失败，消息应该被重新投递或进入死信队列。 
		 // - 如果ES写入失败，需要记录日志，并通过定时任务或手动方式进行重试，以保证数据最终一致性。 System.err.println("数据同步失败: " + e.getMessage()); 
		 // throw new AmqpRejectAndDontRequeueException("ES sync failed"); // 例如，让消息进入死信队列 
		 } 
	 }
```


> 数据查询

前端发来的查询数据请求由数据库查询改为从 `es` 中查询。
```java
	public Page<VideoDocument> search( @RequestParam(required = false) String keyword, 
	@RequestParam(required = false) String category, 
	@RequestParam(defaultValue = "0") int page, 
	@RequestParam(defaultValue = "10") int size) { 
		// 1. 构建查询条件 
		NativeQueryBuilder queryBuilder = new NativeQueryBuilder(); 
		BoolQueryBuilder boolQuery = QueryBuilders.boolQuery(); 
		if (keyword != null && !keyword.isEmpty()) { 
			// 对标题进行全文检索 
			boolQuery.must(QueryBuilders.matchQuery("title", keyword)); 
		} 
		if (category != null && !category.isEmpty()) { 
			// 按分类进行精确过滤 
			boolQuery.filter(QueryBuilders.termQuery("category", category)); 
		} queryBuilder.withQuery(boolQuery); 
		
		// 2. 添加分页和排序 (例如按创建时间降序) 
		queryBuilder.withPageable(PageRequest.of(page, size, Sort.by(Sort.Direction.DESC, "createTime"))); 
		
		// 3. 执行查询 (直接查ES，不再查数据库) 
		SearchHits<VideoDocument> searchHits = operations.search(queryBuilder.build(), VideoDocument.class); 
		SearchPage<VideoDocument> searchPage = SearchHitSupport.searchPageFor(searchHits, queryBuilder.getPageable()); 
		
		// 4. 返回结果给前端 
		return (Page<VideoDocument>) SearchHitSupport.unwrapSearchHits(searchPage); 
	}
```

对应的 `es` 查询语句：
```shell
	POST /video_index/_search
	{
	  "query": {
	    "bool": {
	      "must": [
	        {
	          "match": {
	            "title": "一些搜索关键词" 
	          }
	        }
	      ],
	      "filter": [
	        {
	          "term": {
	            "category": "科技"
	          }
	        }
	      ]
	    }
	  },
	  "from": 0,
	  "size": 10,
	  "sort": [
	    {
	      "createTime": {
	        "order": "desc"
	      }
	    }
	  ]
	}
```

## 有什么问题？

### 双写问题

问题的根源在于“双写”：你需要先写数据库，再写 ES（或者反过来）。这两个操作不属于同一个事务，因此在任何一步都可能失败，导致不一致。

上述代码中使用了双写同步的方案，具有以下缺点：
- **性能差**：API的响应时间是“写DB耗时 + 写ES耗时”的总和。
- **可用性低（紧耦合）**：如果ES集群出现故障或网络抖动，导致写入失败或超时。
- **无法保证一致性** ： 如果步骤2失败，你无法简单地回滚步骤1的数据库事务（因为它已经提交了）。这仍然会导致数据不一致。

>解决方案1： 异步消息写入 ES（主流）

**流程如下：**

1. 业务方发起写请求（新增/修改）。
2. 应用服务将数据写入数据库。
3. **成功写入数据库后**，向MQ发送一条消息，消息内容可以是视频的ID或完整的数据。
4. 一个独立的消费者服务（可以同一个应用内）监听MQ
5. 消费者收到消息后，查询数据库获取最新数据，然后写入到ES中。

**优点：**

1. 高吞吐和低延迟
2. 解耦、高可用
3. 失败重试

**还会有什么问题？**

“写DB”和“发送MQ消息”这两个操作也不是原子的。如果在DB提交后、MQ发送前，服务器宕机了怎么办？数据依然会不一致。因此还需要引入一张本地消息表与 MQ 的事务消息。
1. 在同一个事务中提交`video`表数据与`消息`表数据，操作保证了原子性。
2. 一个独立的、可靠的“中继服务”（或定时任务）不断扫描`message_outbox`表，将“待发送”的消息发送到MQ（事务消息，将提交数据与更改数据库数据为同一个事务），成功后再将消息状态更新为“已发送”。



>解决方案2：监听数据库变更CDC （终极解决方案）

**流程**：

1. 业务应用**只管操作数据库**，完全不需要关心ES或MQ的存在。
2. 部署一个CDC（Change Data Capture）工具，如 **Canal** (阿里巴巴开源)、**Debezium** 等。
3. CDC工具伪装成一个MySQL的从库，实时订阅并解析Binlog日志。
4. 当CDC工具监听到`video`表有`INSERT`, `UPDATE`, `DELETE`操作时，它会捕获这些变更数据。
5. CDC工具将变更数据投递到MQ中（通常是Kafka）。
6. 消费者服务从MQ获取数据，写入ES。

**缺点：**

1. 架构复杂度高
2. 对数据库有一定要求，需要开启 `Binlog`
